# PulseChat Threat Model

| Threat | Attack | Mitigation | Verification | Residual Risk |
| :--- | :--- | :--- | :--- | :--- |
| **Stolen Access Token** | Attacker steals a JWT from memory/network and replays it indefinitely | Short 15-minute access token TTL (`sid` bound to revocable `Session`); `socket.use()` rejects expired tokens with `auth:expired` and disconnects after 30s | `sessionsAndTokens.test.js` | Valid for up to 15 minutes until expiry or explicit session revocation |
| **Stolen Refresh Token** | Attacker steals `refreshToken` and rotates it before or after the legitimate user | Stored as SHA-256 hash only in `httpOnly`, `SameSite=None; Secure` (prod), `Path=/api/auth` cookie; atomic rotation via `findOneAndUpdate`; replay of `previousTokenHash` outside 10s grace window revokes the entire session family and disconnects sockets | `sessionsAndTokens.test.js` | Replay within the 10-second multi-tab grace window is tolerated before triggering family revocation |
| **Session IDOR & Hijacked Device** | Attacker guesses another user's session ID to enumerate or revoke it, or continues using a revoked device | `GET /api/auth/sessions` and `DELETE /api/auth/sessions/:id` scope queries to `req.user.id` (returning `404` otherwise) and omit token hashes; `requireAuth` checks active session status and revocation emits `session:revoked` + disconnects sockets | `sessionManagement.test.js` | `lastActiveAt` updates are throttled to once per 5 minutes to avoid DB write amplification |
| **Credential Stuffing & Enumeration** | Attacker probes usernames via login timing/error differences or reuses breached passwords | Dummy `argon2id` verification on unknown users (`verifyDummyPassword`), identical `401` error for wrong user/password, and k-anonymity HIBP range check (`Add-Padding`, 1.5s fail-open) on register/password change | `passwordSecurity.test.js` | HIBP fails open during upstream outage; registration returns `409` for taken public usernames |
| **Distributed Brute-Force / Lockout DoS** | Attacker rotates IPs to brute-force a victim's password or intentionally triggers hard account lockout | Per-account exponential backoff (`30s`, `1m`, `5m`, `15m` cap after 5 failures) with `Retry-After` header alongside per-IP rate limiting; resets on success | `passwordSecurity.test.js` | Victim experiences up to 15m temporary delay under active distributed attack rather than permanent lockout |
| **Brute-Forcing / Replaying 2FA** | Attacker replays a captured TOTP code, brute-forces 6-digit codes, reuses a recovery code, or uses `mfaToken` on other routes | AES-256-GCM encrypted TOTP secrets at rest (`keyId` prefixed); `twoFactorLastStep` rejects TOTP replay; single-use atomic recovery code consumption; `mfa_pending` token lacks `sid` and fails on all other REST/socket endpoints; per-account exponential backoff + IP rate limit | `twoFactor.test.js` | A +/-1 step (30s) drift window allows valid codes from adjacent steps if not yet used |
| **Cross-Site Request Forgery (CSRF)** | Malicious site triggers `POST /api/auth/refresh` or `/logout` using `SameSite=None` cookies | `requireCsrf` enforces `Origin === CLIENT_URL`, custom `X-Requested-With` header, and timing-safe double-submit `X-CSRF-Token` matching `csrfToken` cookie; Bearer-authenticated routes are non-CSRF-able | `webHardening.test.js` | Requires strict `CLIENT_URL` origin configuration |
| **NoSQL Operator Injection** | Attacker sends `{ "$gt": "" }` or `{ "$ne": null }` in login/room/query payloads | `sanitizeNoSql` middleware strips `$` and `.` keys from `body`/`query`/`params`, `mongoose.set('strictQuery', true)`, and Zod enforces string/ObjectId types before Mongoose queries | `webHardening.test.js` | Relying on application-layer validation; MongoDB query builders must never bypass Zod |
| **Socket Flood / Origin Spoofing / DoS** | Attacker connects from untrusted origin, opens hundreds of sockets, sends huge frames, or spams unknown events | `allowRequest` enforces `CLIENT_URL` origin; `maxHttpBufferSize` capped at 100 KB; max 10 sockets/user & 30/IP; explicit event allowlist disconnects after 3 unknown events; 60 events/10s global per-socket cap | `webHardening.test.js` | Single-node in-memory socket counters until Redis adapter is enabled |
| **Audit Log Tampering / Secret Leakage** | Attacker or compromised admin deletes/mutates audit trails, reads logs as a regular user, or exploits audit metadata containing passwords/tokens/message text | `auditService` exposes only append (`audit`) and read (`queryAuditEvents`) with no update/delete methods; `sanitizeMetadata` strips keys matching `password`, `token`, `secret`, `text`, `message`, `code`, `hash`, `key`; `GET /api/admin/audit` enforces `requireAuth` + `requireAdmin` (DB-backed `globalRole === 'admin'`) | `auditAndFlood.test.js` | Direct database root access could still alter MongoDB collections |
| **Room Flooding & New-Account Spam** | Automated bots register fresh accounts to flood rooms with duplicate spam, bypass slow mode, initiate unsolicited DMs, or abuse file upload presigning | Per-room `slowModeSeconds` cooldown, duplicate-message spam heuristic (blocks 3rd identical message in 30s), tighter socket rate limit (`3/10s` vs `10/10s`) and `NEW_ACCOUNT_RESTRICTION_MINUTES` gate blocking `POST /api/rooms/dm` and `POST /api/uploads/presign` for newly created accounts | `auditAndFlood.test.js` | In-memory slow-mode/spam maps are per-node until backed by Redis |
| **Malicious Uploads (Malware, EXIF GPS, Type Spoofing, SVG XSS)** | Attacker uploads an EICAR/infected payload, an HTML/SVG script disguised as `image/png`, or an image containing sensitive EXIF GPS coordinates | Presigned PUTs target `quarantine/<roomId>/` and remain non-downloadable (`scanStatus: 'pending'`, `url: null`) until `scanWorker` scans with `clamd`, checks magic bytes (`file-type` + text checks), strips EXIF/GPS/polyglot payloads via `sharp` re-encoding, and promotes only clean files to `uploads/<roomId>/`; SVG is blocked at presign and scan; `Content-Disposition: attachment` forced on non-images | `uploadSafety.test.js`, `uploads.test.js` | Requires `clamd` (`CLAMD_HOST`) running in production/Compose to process quarantine queue |
| **Privilege Escalation & Role Bypass** | Member promotes self to owner, moderator kicks admin, admin demotes owner, or global admin reads private rooms/DMs | Central `can()` / `assertCan()` in `services/permissions.js` enforces the declarative role hierarchy (`owner > admin > moderator > member`), prevents last-owner demotion/leave, blocks global admins from private rooms/DMs unless explicitly a member, and audits every role change & removal | `permissions.test.js` | Relies on every new handler calling `can()` / `assertCan()`, enforced by a handler-import test |
